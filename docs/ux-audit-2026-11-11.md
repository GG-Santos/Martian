# Focused UX audit — baseline, 2026-11-11

Scope: first-use Mission Command, Crew setup, Astronaut Map, Quest Board; desktop 920–1440 px and narrow 390 px; pointer and keyboard flows. Sources: user browser comment on Home plus direct Playwright screenshots and existing journey tests. This is a focused audit using Cognitive Load, Choice Overload, Common Region, Transparent, Visual Interference, and Resilient; payment and consent flows do not exist. Strength: NASA source attribution and explicit Jezero simulation caveats already appear.

## Prioritized findings

1. **High / high confidence — mission identity and map purpose are conflated.** Home has one static Jezero image, while Astronaut Map is both a planning atlas and live mission console. A user cannot compare destinations before forming a crew, and the same dense screen must serve discovery and action. Evidence: Home `Archived Jezero terrain overview` is the only site preview; its `Explore the map` link opens the astronaut scanner. Relevant lenses: Cognitive Load, Common Region, Choice Overload. Remedy: location carousel and dedicated Explore Map, then mission-specific Astronaut dashboard. Verify a new user can name the selected site and find the crew flow without entering operations.
2. **High / high confidence — astronaut hierarchy is still the old scanner.** At 1280×720, the Jezero terrain occupies a small square between an eight-category science rail, 14 map controls and a right column of journal data. Live crew controls require a separate tab. Relevant lenses: Cognitive Load, Visual Interference. Remedy: new field dashboard with map, active crew, and risk first; put complete science scanner behind a labeled advanced-data route. Verify crew movement and status are visible within one viewport.
3. **Medium / high confidence — crew identity is only text.** The current `/crew` form asks for name/role and the lobby displays text rows, so members cannot recognize a distinctive 3D teammate on the map. Relevant lenses: Common Region, Aesthetic-Usability Effect. Remedy: original simple 3D character creation, persist it in room snapshots, and render it in lobby and map. Verify four unique avatars across two browsers and reconnect.
4. **Medium / high confidence — quest location requires translation.** The board asks for Map X and Map Y numbers without a selectable map in the posting flow. A user must infer coordinates elsewhere and retype them. Relevant lenses: Cognitive Load, Resilient. Remedy: click-to-place map pin synchronized with numeric fields, disclose map provenance and bounds. Verify an intended location can be selected visually and survives publication.
5. **Medium / high confidence — simulation can feel absent rather than informative.** Weather/radiation are context archives, and live oxygen/stamina are numbers without a compact scenario view. Relevant lens: Transparent. Remedy: styled simulated environment and suit indicators with persistent simulated provenance, scenario changes, and route consequences. Verify no element implies current NASA weather or certified EVA safety.

Coverage: 6 focused lenses assessed across 4 screens. No deceptive-pattern label assigned; the observed problems are hierarchy and task friction, not evidence of manipulative intent. Post-change screen checks and remaining unknowns will be recorded after implementation.

## Post-change visual review

Reviewed fresh 1440×900 and 390×844 full-page captures in `docs/screenshots/atlas/` after the atlas changes. Each page had no horizontal overflow. The browser journey suite also exercised navigation, map selection, crew synchronization, quest posting, and the original scanner.

| Screen | Visual finding and change | Remaining risk |
| --- | --- | --- |
| Mission Command | The carousel now shows Jezero, Gale, and Melas Chasma in equal frames. A second pass removed the repeated status strip, label, and unselected science goal, moved carousel dots away from the caption, and used a wide Gale image crop. | The third carousel choice requires an arrow or dot selection; first-time users may not notice it. Gale has archived imagery but no registered local terrain grid. |
| Explore Map | The 1480×714 review replaced both sidebars with a full-width, rotatable globe. Destination markers open a temporary fact panel with a NASA source link. The global sphere uses Viking imagery and a visually exaggerated MOLA elevation mesh; 5,041 J2000 stars replace random stars. | Planetary relief is exaggerated for legibility, and the sky is a fixed catalog view rather than live Mars orientation. Global MOLA resolution cannot support local route safety. |
| Crew | Character controls and a rendered 3D preview are visible before the form; the waiting room presents four avatar slots and readiness after joining. | On a narrow phone, creation controls push the join form below the first viewport. |
| Astronaut Map | 3D local terrain leads; five compact status cells expose crew, oxygen, stamina, tasks, and network. Simulated environment controls are grouped in one side panel, and the legacy data scanner is a separate destination. Removed the repeated no-room live expedition prompt. | The side panel still grows long during active missions; route details require scrolling on phones. Character markers are deliberately not to scale. |
| Quest Board | The empty state now previews proposed objectives on a map, and selecting a row changes the map pin. After joining, posting offers click and keyboard pin placement with numeric coordinates alongside. | Map preview is Jezero-only before joining; crew-specific missions use their selected sector after joining. |

The remaining items are usability limits, not claims of operational safety. Observed Jezero products and simulated Gale/Melas terrain, weather, radiation, resource, zone, and route scenarios stay labeled at their point of use. Radiation scenario warnings do not imply a calculated dose.

The latest 390×844 Explore capture found a cropped globe and a fact panel extending below the screen. The viewport-width camera fit and header-aware canvas height now show the full globe and both panel links without horizontal overflow. On the mobile Mission Command capture, the second copy of the selected destination heading is hidden; the image caption remains the location label.

## Follow-up visual review, 2026-11-12

The homepage now uses its right panel for the Space Apps challenge, while the image carousel shows one NASA-sourced place fact at a time. This removes the repeated location heading, destination counter, and non-informative preview caption. The atlas header uses three larger navigation targets with a clear active state. The globe shows named-feature dots only on the visible hemisphere, with the three mission regions labeled; selecting a point centers it and opens source details. The additional 44 Gazetteer points provide global coverage, though unlabeled dots require selection to learn their names. This is an intentional overview density trade-off that merits future usability testing.
